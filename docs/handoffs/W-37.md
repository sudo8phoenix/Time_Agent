## Behavior implemented

`GET /api/v1/jobs/{job_id}/agent-run` scopes the job through the authenticated user’s project membership using `_job_for_user`. Any in-project member may read status; a job outside the member’s projects and a job without a graph run both return 404. Legacy execution records are excluded.

The response uses the strict W-32 `AgentRunResponse` schema. It returns the fixed known graph/framework versions or `unrecognized` when stored values differ, public stage labels, exact bounded counters, and steps ordered by ordinal and ID. Only allowlisted error codes and fixed messages are returned. Database error messages, run metadata, summaries, prompts, report text, checkpoint contents and other trace fields are never serialized. The response sets `Cache-Control: no-store`.

## Response examples

Successful member read (`200`):

```json
{
  "id": "<run UUID>",
  "job_id": "<job UUID>",
  "graph_version": "report-analysis-v1",
  "framework_version": "langgraph-1.2.12/checkpoint-postgres-3.1.2",
  "state": "running",
  "current_stage": "Loading context",
  "counters": {
    "node_executions": 3,
    "extraction_calls": 1,
    "selection_calls": 0,
    "corrective_retries": 0
  },
  "steps": [],
  "error_code": null,
  "error_message": null,
  "started_at": "<timestamp>",
  "updated_at": "<timestamp>",
  "completed_at": null
}
```

Missing, legacy, or out-of-scope job (`404`): `{"detail":"Job not found"}` or `{"detail":"Agent run not found"}`. Unauthenticated requests receive `401`; no role-based `403` is used because both reviewers and viewers may read an in-project run.

## Limitations and acceptance state

This endpoint exposes status only. It does not expose checkpoint data or support retry, node control, approval or prompt selection. W-37/W-38 are accepted. W-39 local-prototype evidence includes parity, recovery, rollback, live smoke and browser-to-running-API/worker/model verification; see [W-39](W-39.md). Independent evaluation and release gates remain open.
