# F01 — Reusable discipline report mapping

Status: `implemented`, `verified_fixture`. Complete for the prototype; no independently reviewed labels or live-model accuracy claim.

## Delivered

- `ingest/report_mapping.py`: bounded XLSX sheet/header previews, explicit canonical column indices, file discipline/area/date context, native Excel dates/times, source number formats and date-only precision, explicit D/M/Y versus M/D/Y selection, header signatures, and row/cell error inventory. Quantity is optional. Formula cells require explicit values. Any invalid nonempty row blocks intake; rows are never silently omitted from a processing job.
- `ReportMapping` plus additive migration `0013_report_intake`, following `0012_integration_outbox`: project/template/header signature/revision, confirming actor/time and immutable spec. Revision creation locks the project. Original report bytes and original headers/cells/types/number formats/locators are retained in report intake metadata.
- Project-authorized, CSRF-protected preview and save APIs; upload accepts a confirmed `mapping_id`, checks project and actual header signature and refuses changed headers. Confirmed mapping revision accompanies source provenance in review. Legacy canonical ingestion remains available.
- Intake UI previews original cells, maps fields, selects/rechecks saved templates, confirms/saves mappings and displays row errors. Mapping edits invalidate confirmation. No progress is applied by intake.
- Synthetic report-shaped `civil-diary.xlsx`, `electrical-diary.xlsx`, and `civil-diary-next.xlsx` in `data/synthetic/v2/intake/`. These are developer-authored reports, not source schedules, owner data or independent gold labels.
