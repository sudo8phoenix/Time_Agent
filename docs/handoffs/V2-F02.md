# F02 — Diary/PDF and immutable scan transcription

Status: `implemented`, `verified_fixture`. Complete prototype flow; no live-model or independent-review claim.

## Delivered

- PDF parser keeps every page, including pages without text, with `page:N` evidence locators and `NEEDS_TRANSCRIPTION` quality flags. Encrypted/malformed PDFs are validation errors. Unreadable PDFs create recoverable `needs_transcription` jobs immediately rather than disappearing or entering model processing. This intake gate applies before either worker execution mode. Legacy pipeline also checks fragment flags.
- Project-authorized original download/inline PDF endpoint preserves immutable source bytes outside the static tree.
- Reviewer/CSRF-protected append-only transcription endpoint validates original page numbers, requires all unreadable pages, carries forward readable pages and the trusted report date, and creates a linked child report/job. It preserves original report/file identity, page locators, human-text quality, transcriber and UTC time. Retry identity excludes actor/time so duplicate submissions reuse the same child job. Original scan/fragments are unchanged. Changed text creates a separate immutable child report.
- Job UI displays embedded original pages beside the page transcription fields, original extracted text and an original-source link. Submission returns to the normal review job flow and survives job-history recovery. Review provenance shows source link, transcription attribution and immutable intake metadata alongside extracted evidence.
- Sanitized synthetic raster diary `data/synthetic/v2/intake/scan-diary.png`, compressed RGB fixture, and text diary. Integration tests construct text and image-only PDFs from these fixture sources in memory. No OCR or source schedule Gantt PDF is used as a diary.
