# H01 — Execution history, exports and recurring blockers

Status: `implemented`, `verified_fixture` (10 October 2026). No live-model accuracy or independent source-review claim.

## Delivered

- Project-member-authorized `/projects/{project_id}/history` provides schedule-version pinning, activity/discipline/work-type/work-date/blocker-category/status/correction filters and bounded offset pagination (maximum 200). Accepted events retain original values, including superseded originals and retraction tombstones. A retraction marks its entire ancestor correction chain withdrawn, so originals cannot resurrect. `active_only` is separate from the full history default.
- CSV and JSON exports include internal and schedule external activity IDs, discipline, work type, WBS, scope/subactivity/parent, event kind, precision-preserving endpoint, quantity/unit, blocker/category, evidence with fragment/cell/page locators, separate confidence estimates, original report/source/hash, pinned version, model/prompt/config metadata, actors, decisions and corrections. `accepted_values` records event-time values. Nested `latest_activity_state` in JSON and `latest_*` CSV columns explicitly identify the current projection. The old ambiguous current-state CSV column names are replaced; CSV consumers must adopt the explicit names. Every CSV cell retains formula-injection protection. JSON retains nested provenance and decisions.
- Blocker observations create quantity-free evidenced effects in the shared legacy/graph effect builder. Authorized acceptance validates the category, date, source report and quotes; it stores an immutable event without modifying quantities or lifecycle dates and without sending a spurious PMIS state update. Acceptance still uses project membership, pinned eligible activity, revision locks, warning resolution and idempotency. A review category defaults visibly to `other`; the reviewer may revise it before acceptance. Categories are access, design, equipment, inspection, labour, material, safety, weather and other. Acceptance records the category decision; it does not independently establish domain truth.
- `/proposals/events/{event_id}/correct-blocker` creates a new pending evidenced proposal with actor/reason and immutable parent lineage. Approval requires a currently active blocker target. Multiple stale corrections cannot replace an already replaced event. `/projects/{project_id}/blockers` counts only active accepted causes, so accepted corrections are counted once; each cause carries up to 20 history/evidence links. Independent repeated observations are separate events, not silently merged.
- Approved progress embeds a responsive execution-history panel, activity selection by name/ID, filters, explicit status, original evidence links, event/current-state details, JSON/active CSV export, recurring-cause evidence navigation and pagination. Per-activity historical rows also label active/superseded/retracted status and do not offer lifecycle correction on inactive events. H02 duration queries appear alongside history.

## Limits and next task

History pages retrieve bounded detail rows, but correction status calculation scans lightweight event IDs/kinds/parent references for the selected version. Bulk exports and blocker aggregation cover all selected events. Large-history streaming/index benchmarks are not claimed. External activity ID means the immutable schedule external ID used by the current mock mapping; no production PMIS ID mapping is invented. Unknown historical metadata remains explicitly unavailable. Unmatched blockers still need pinned eligible activity resolution before acceptance. Calendar and labour data limitations are documented under H02.
