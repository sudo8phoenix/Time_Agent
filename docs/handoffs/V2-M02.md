# V2 M02 — explicit subactivity mapping

Status: `implemented`, `verified_fixture`. Completed 10 October 2026. Default remains no inferred roll-up; no database migration required.

## Changes

- `LifecycleEffect` represents named subactivity identity and optional scheduled parent UUID. Approval binds that parent to the chosen executable activity in the pinned snapshot; mismatched parents, summaries and whole-activity effects carrying child mappings are rejected.
- The immutable event's `approved_values` stores `subactivity_key`, `scheduled_parent_id`, scope and source evidence. Named child identity must occur in a validated source quote annotated for scope/identity. Reviewer scope/identity edits require a saved revision and reason. A canonical name absent from the source quote must be revised to evidenced terminology or supplied through an amended report.
- Existing lifecycle reduction continues to exclude child events from whole-activity state. Acceptance now also avoids assigning a child event as the parent's actual-start/finish event reference. No complete-child aggregation rule is introduced.
- Review displays editable scope, child identity and scheduled parent name. Progress history displays scope, child identity and the parent's external activity ID. JSON history and CSV export include child identity and scheduled parent UUID alongside scope and endpoint precision.
