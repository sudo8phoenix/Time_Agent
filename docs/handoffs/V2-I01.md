# V2 I01 — transactional outbox and mock PMIS

Status: `implemented`, `verified_fixture`. Completed 10 October 2026.

## Behavior

Approval (lifecycle or numeric), accepted correction, and lifecycle retraction enqueue a complete activity-state snapshot in the acceptance transaction. Rollback removes both effects and the outbox row; existing actor/project authorization, schedule pinning, revision locks and approval idempotency remain in place. External failure leaves the internally accepted state intact.

The separate worker drains committed rows automatically. It holds a PostgreSQL row lock during bounded local HTTP delivery, selects with `SKIP LOCKED`, and prevents later revisions overtaking unresolved older revisions for the same activity. Transient failures retry with capped exponential backoff; mapping/version/contract failures become `failed` and block subsequent revisions for that activity. Attempts, last attempt, retry deadline, delivery receipt and read-back verification are persistent and visible through authenticated project progress and paginated `/api/v1/projects/{project_id}/integration-deliveries`.

The loopback receiver is labelled **MOCK PMIS — prototype**, persists state and receipts in SQLite, rejects same-key/content and same-revision/state conflicts, and ignores late older revisions. Its activity read-back endpoint is `/activities/{external_project_id}/{source_schedule_version_id}/{external_activity_id}`. The connector verifies read-back before marking delivery successful. A receiver-success/worker-timeout retry returns the original receipt without applying again.

The prototype uses an explicit deterministic mapping: external project ID = internal project UUID; external activity ID = source schedule external activity ID; schedule UUID forms the receiver namespace. New mappings are registered by the first valid snapshot. This is a mock mapping policy, not a production PMIS integration. Full state endpoints preserve date/time/precision/timezone/basis/raw expression where present. Date-only values carry null time; no midnight is fabricated. Subactivity events enqueue the unchanged parent state without promoting child completion.

## Run locally

After the normal application database migration is explicitly authorized, migration `0012_integration_outbox` follows `0011_conversations`. This implementation only migrated the isolated `progress_test` database; the user's application database was not migrated.

From the repository root, in two terminals using the same application configuration:

```sh
.venv/bin/python ops/mock_pmis_server.py --db /tmp/mock-pmis.sqlite3 --port 8091
.venv/bin/python ops/run_connector.py --url http://127.0.0.1:8091
```

Keep the receiver SQLite file to retain mock state across restarts. Use a dedicated path per demo environment. `--once` on the connector processes at most one eligible snapshot. The worker never contacts non-loopback destinations. Open Approved progress and use Refresh delivery status to see acknowledgement/errors. The source API's normal authentication applies; the receiver has no authentication and binds only to loopback.

Failed contract/mapping deliveries require operator investigation and correction of the receiver/configuration before a deliberately audited administrative retry; no unrestricted retry or payload-edit UI is supplied. Later revisions remain blocked rather than silently skipping rejected state. Transient failures recover automatically. The worker requires a separately running process; acceptance only queues the durable message.
