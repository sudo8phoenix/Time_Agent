## Callable signatures

`AgentTools(context, *, extraction_service=extract_fragments, retrieval_service=retrieve_candidates, selection_service=select_candidate, persistence_callback)` creates one ephemeral tool adapter. It is constructed per graph invocation and is not part of `AgentState`.

The six public tool methods are:

```text
load_job_context(job_id: str) -> JobContextResult
extract_observations(fragment_ids: list[str], report_metadata: ReportMetadata) -> ExtractionToolResult
retrieve_candidates(observation_key: str, observation: Observation, schedule_version_id: str) -> RetrievalToolResult
select_candidate(observation_key: str, observation: Observation, candidates: list[Candidate], fragment_ids: list[str]) -> Proposal
validate_proposal_drafts(state: AgentState) -> ValidationToolResult
persist_review_proposals(state: AgentState) -> PersistenceResult
```

`ReportMetadata` contains only `report_date` and `report_date_trusted`. `JobContextResult` returns canonical job/project/report/schedule UUID strings and ordered fragment/activity UUID lists. Extraction results use frozen W-33 `ModelMetadata`, `ValidationErrorRecord`, and `AgentWarning`; retrieval and validation use frozen `AgentWarning` and validation records. Every result is an extra-forbidden Pydantic model.

O-04 correction: `AgentTools.report_metadata` is a read-only property, not a seventh tool. It requires loaded scope and returns a fresh strict object populated only from the server-loaded report date and trust flag. Before context load it fails with safe `AGENT_TOOL_FAILED`; mutating a returned object cannot alter retained metadata.

O-04 retry-classification correction: `AgentToolError.stage` and `.retryable` expose immutable, safe metadata with nonretryable defaults. Only known extraction/selection schema, evidence, date, count, or service-specific validation failures are tagged with their stage and retryable status. Scope, forged input, provenance, budget, unknown service/transport failures remain nonretryable. Draft validation returns sanitized `ValidationErrorRecord` categories; it does not include raw validator details.

## Scope, result and error behavior

`load_job_context` reads the current job, project, report, pinned schedule, report fragments ordered by ordinal/UUID, and leaf activities ordered by UUID using the injected session factory. It requires a running job with the matching unexpired lease and verifies the report, project, schedule and fragment/activity relations. It privately retains detached fragment text/locators and leaf activity values. Lease failures return `JOB_LEASE_LOST`, active schedule changes return `SCHEDULE_VERSION_STALE`, and other safe failures return `AGENT_TOOL_FAILED`.

Subsequent methods require this loaded scope. Extraction accepts exactly the complete ordered fragment ID list, rebuilds `FragmentInput` from server-loaded rows, passes only server-derived report metadata to `extract_fragments`, validates evidence membership and trusted relative dates, canonicalizes/deduplicates observations, and rejects more than 200. Its two-call budget returns `AGENT_REPAIR_LIMIT` when exhausted.

Retrieval only sees retained leaf activities from the pinned schedule. It validates unique known leaf candidates and the eight-candidate limit. Optional embedding failures fall back to lexical retrieval with a stable warning. Selection requires the extracted observation for the requested run-local key and a subset of the exact candidates previously returned for that key. It allows two calls per observation key, checks evidence IDs and candidate membership, prohibits proposed effects, and validates abstentions. Empty retrieval delegates the deterministic abstention without a model callable.

Validation enforces exact W-33 observation/candidate/selection keysets, exact state identity and scope, extracted observation membership, scoped evidence, retrieved candidate equality, selected candidate membership, proposal candidate non-expansion, and empty proposed effects. Persistence runs that validation again, freshly rechecks lease, schedule and job relationships, then calls the required callback at most once with `idempotency_key=state.run_id`. A successful strict result is cached; result counts must match observation and proposal counts. Callback failures and invalid results are converted to `AGENT_TOOL_FAILED` and are not retried by the wrapper.

Service, model and database exception bodies are not exposed. `AgentToolError` carries a stable `code` and safe message. No approval, progress, generic registry, dispatcher or model-controlled routing code is imported.

## Contract notes and next task

No shared service or schema files were changed. The current pipeline does not expose a dedicated graph persistence function, so W-34 implements the specified callback contract without claiming persistence semantics beyond the callback's strict result and idempotency-key interface. The graph integration must inject the transaction-aware persistence callback supplied by O-04/W-35 integration.

The six frozen tool signatures do not append validator text to prompts. On a retryable validation result, the graph triggers one rerun of the same reviewed bounded extraction or selection call. No generic repair prompt or repair tool is added. W-35 can assemble the bounded graph using these callable signatures and safe retry metadata.
