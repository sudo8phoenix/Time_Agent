# V2 T01–T02 — text conversation

Status: implemented and verified through isolated PostgreSQL, HTTP, and a live-model browser flow. M01 has not started. The user `progress` database was not migrated.

## Changed

- Migration `0011_conversations` stores project-scoped conversations, immutable turns, pinned schedule version, draft revision, clarification state, confirmation and review job linkage.
- Authenticated, CSRF-protected create/list/read/message/retry/edit/confirm/cancel endpoints enforce ownership and optimistic revisions. Confirmation creates reviewer proposals without updating activity state. Status follows the latest revision of each proposal and becomes `accepted` only after every proposal is approved.
- Conversation analysis reuses extraction and lifecycle effects. A missing date, ambiguous location or unclear finish scope produces a focused question. A trusted report date or user answer is stored as evidence. Date-only statements stay date-only. A quoted exact area and work type can select a single pinned schedule activity without extra model calls; ambiguous matches still use the existing shortlist and selection path.
- Event cards expose evidence and allow corrections to the pinned candidate, local date/time, date-only precision, and whole-activity or named-part scope. Corrections add an immutable user turn and source fragment, then rebuild the lifecycle effect.
- The Text log persists turns and drafts, shows pending-review and accepted states, supports retry after model failure, and preserves unsent text in tab storage. Mobile layout keeps the composer usable with a reduced viewport.

## Known limitation

The live model can be slow or return malformed structured JSON. The API saves the user's turn and shows a retry state on those failures. The exact quoted-area path removes two subsequent model calls when the evidence identifies one scheduled activity, but extraction still depends on the model. Neither model behavior nor activity matching is an unseen accuracy benchmark.
