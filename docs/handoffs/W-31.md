## Checkpoint tables and package setup inventory

Inspection of installed `langgraph.checkpoint.postgres.base.MIGRATIONS` for checkpoint-postgres 3.1.2 showed these package-owned tables:

- `checkpoint_migrations(v INTEGER PRIMARY KEY)`
- `checkpoints(thread_id TEXT, checkpoint_ns TEXT DEFAULT '', checkpoint_id TEXT, parent_checkpoint_id TEXT, type TEXT, checkpoint JSONB NOT NULL, metadata JSONB NOT NULL DEFAULT '{}', PRIMARY KEY(thread_id, checkpoint_ns, checkpoint_id))`
- `checkpoint_blobs(thread_id TEXT, checkpoint_ns TEXT DEFAULT '', channel TEXT, version TEXT, type TEXT, blob BYTEA, PRIMARY KEY(thread_id, checkpoint_ns, channel, version))`
- `checkpoint_writes(thread_id TEXT, checkpoint_ns TEXT DEFAULT '', checkpoint_id TEXT, task_id TEXT, idx INTEGER, channel TEXT, type TEXT, blob BYTEA NOT NULL, PRIMARY KEY(thread_id, checkpoint_ns, checkpoint_id, task_id, idx))`

The installed package migrations also drop `NOT NULL` on `checkpoint_blobs.blob`; contain a no-op `SELECT 1`; create concurrent indexes `checkpoints_thread_id_idx`, `checkpoint_blobs_thread_id_idx`, and `checkpoint_writes_thread_id_idx`; and add `checkpoint_writes.task_path TEXT NOT NULL DEFAULT ''`. O-04 ran package setup only against `progress_test` and confirmed this inventory. Per contract §8, it is evidence for W-36 migration planning, not authorization for application startup DDL.

The smoke defaults `LANGGRAPH_STRICT_MSGPACK=true` before importing LangGraph. Its graph stores only a primitive integer field. It refuses all database names except `progress_test`; test-row cleanup (if reached) is by exact unique `thread_id` in each saver table.
