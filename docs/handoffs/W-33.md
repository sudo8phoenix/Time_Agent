## Behaviour and exported names

The package exports `AgentState`, `AgentStateError`, `create_initial_state`, `encode_agent_state`, `decode_agent_state`, `observation_keys`, `validate_identity_transition`, `AgentRuntimeContext`, `AgentPolicyError`, `route_next_action`, and `public_stage`.

`AgentState` contains exactly the contract's logical fields and uses the existing strict `Observation`, `Candidate`, and `Proposal` models. The concrete versions are `schema_version="agent-state-v1"`, `graph_version="report-analysis-v1"`; UUID identities and fragment/activity IDs must be canonical lowercase UUID strings. State counters have exactly four fields; only `create_initial_state` supplies omitted zero defaults, while incomplete explicit or resumed counters fail. The observation fixture follows `backend/app/schemas/observation.py`; run-local keys are `obs-0001`, `obs-0002`, etc. Nonempty candidate and selection maps must each exactly match the expected observation keys, and nonempty maps must match each other. Each candidate list is capped at eight and total observations at 200.

`AgentRuntimeContext` is a frozen slotted dataclass with exactly `session_factory`, `lease_token`, `model_callable`, `embedder`, `heartbeat_callback`, `shutdown_callback`, and `clock`. It is not a state field. State uses strict extra-forbidden models; encode/decode helpers use finite JSON, reject unknown fields/nonfinite data, enforce the 1 MiB UTF-8 limit without truncation, and wrap validation failures in stable `AGENT_STATE_INVALID` or `AGENT_STATE_TOO_LARGE` errors.

`route_next_action`, `route_extraction_validation`, `route_selection_validation`, and `route_persist` are pure and fail closed with `AGENT_STATE_INVALID` on unsupported values. State action `fail` maps only to `record_failure`. Policy limits successful no-repair executions to 12 and executions with repairs to 16; it enforces at most one extraction and one selection repair through explicit `attempted_repairs` inputs and a total corrective retry limit of two. It also exports `validate_observation_and_candidate_limits`, `validate_node_execution_budget`, and `validate_repair_attempt`. Public-stage mapping contains only the ten exact contract §10 labels.

## Error examples

- Unknown state key, uppercase/noncanonical UUID, duplicate fragment ID, invalid nested observation/candidate/proposal, candidate key `obs-0002` for one observation, negative/overflow counter, or any extra runtime/secret field: `AGENT_STATE_INVALID`.
- Missing any counter during decode or incomplete explicit counters in `create_initial_state`: `AGENT_STATE_INVALID`.
- NaN/Infinity nested in encoded state or JSON: `AGENT_STATE_INVALID`.
- Serialized UTF-8 state larger than 1,048,576 bytes: `AGENT_STATE_TOO_LARGE`.
- Observation count beyond 200: `AGENT_OBSERVATION_LIMIT`.
- Invalid route/transition: `AGENT_STATE_INVALID`; over 12/16 graph executions: `AGENT_STEP_LIMIT`; second same-stage or third total corrective retry: `AGENT_REPAIR_LIMIT`.
- Changing any of `run_id`, `job_id`, `project_id`, `report_id`, `schedule_version_id`, `graph_version`, or `schema_version`: `AGENT_STATE_INVALID`.

## Limitations and contract notes

No contract changes requested. Per-stage repair attempts are not represented as separate persisted counter fields in the frozen state; route policy therefore accepts the stage's explicit attempt count from its caller and additionally enforces the state-wide two-repair counter. This follows the assignment's instruction not to add hidden checkpoint fields. The two result dictionaries may be empty before their stages execute; each nonempty dictionary is required to have the exact observation keyset, accommodating the graph's intermediate `retrieve` and `select` states while detecting partial results.
