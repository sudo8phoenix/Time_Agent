# Document input capabilities and security boundaries

Processor inventory audited 20 October 2026; native transport and diagnostic
boundaries updated 21 October 2026 against batch-eighteen code and tests. This is a processor support
inventory, not a claim of measured extraction or model quality. Models receive
text fragments and JSON context; none of the configured model adapters receives
uploaded page images or document binary payloads.

| Input | Processor and delivered model context | Limits and unsupported content |
| --- | --- | --- |
| Pasted text / UTF-8 text upload | UTF-8 decoder; paragraph fragments retain ordinal locators | 10 MiB raw; 2,000,000 extracted characters; no HTML execution or link fetching |
| DOCX | python-docx 1.1.2; top-level paragraphs and table rows in source order | OOXML expansion ≤50 MiB, ≤2,048 entries; images, nested tables, headers/footers, embedded attachments and page layout are not transcribed |
| Text PDF | pypdf 5.1.0; one fragment per page in page order | ≤20 pages; encrypted PDFs rejected; pages with fewer than 40 non-whitespace characters require transcription; attachments, photographs and visual/layout meaning are not read |
| Scan-only PDF | pypdf produces empty/short page text and NEEDS_TRANSCRIPTION markers | Job is blocked for reviewed transcription; there is no OCR or vision processor |
| XLSX report | openpyxl 3.1.5, read-only; required-column reader or explicit revisioned mapping | 10 MiB raw, ≤50 MiB expanded OOXML, ≤2,048 entries; direct reader ≤30 sheets, ≤200 columns, ≤5,000 data rows per sheet; mapped reader ≤200 columns/5,000 rows; preview ≤30 sheets, 20 rows/200 columns; no image interpretation |
| PNG/JPEG/other standalone image | No supported report processor | Explicit unsupported-format failure for image MIME uploads; no downscaling pipeline |
| ZIP/TAR/RAR archive | No general archive intake | Unsupported as report formats; OOXML ZIP is inspected in memory and never extracted to a user-selected path |

Native schedule import is separate: a fixed server dispatch selects XER/P6 XML,
MSPDI XML/MPP, GT10 XLSX or derived Cambridge JSON readers. The model cannot
choose an executable, module, path or destination. Native readers use argument
vectors with shell=False and a 30-second timeout; input ≤10 MiB and returned
output ≤50 MiB per stream. Output is drained concurrently through pipes with
bounded retention; overflow terminates and reaps the isolated process group.
Timeouts also close inherited descendant pipes. CPU is limited to 30 seconds per process; parent-supervised reader RSS is
limited to 1 GiB with finite sampling/termination overshoot. JVM heap is capped
at 512 MiB, metaspace at 256 MiB and direct memory at 128 MiB. Service credentials
and Python/Java injection variables are excluded from the private process
environment. These are per-process controls, not aggregate descendant quotas or
filesystem/network confinement. Child failure messages expose only stable
public codes and generic messages; raw diagnostics are not returned.

Application original-download paths resolve beneath the configured upload root;
escaping and symlink paths are rejected. Non-PDF originals download as
application/octet-stream attachments with nosniff, regardless of uploaded MIME.
Evidence hyperlinks are generated by the application from project/report IDs;
model-proposed URLs are not accepted as executable tool destinations. CSV export
prefixes formula-bearing cells with an apostrophe, including leading whitespace.

## Remaining evaluation boundaries

DOC-01 is satisfied by this inventory: actual processor support is identified,
and no text model is claimed to inspect images. DOC-04 has deterministic database
coverage for scan/short-page gating, reviewed page transcription and prevention
of model invocation before missing text is supplied; representative extraction
and transcription correctness remain separate quality questions.

DOC-05 remains partial. Ordered paragraph/table, page, sheet and row text is
verified, but unsupported attachments, image/layout meaning, nested DOCX content
and full-file completeness are not resolved. Image downscaling is not applicable
because image processing is absent; that does not make DOC-05 itself inapplicable.

SAFE-14 is verified for the current closed tool surface: there are no model-callable
filesystem/network/shell tools, document download paths are confined, and native
reader filenames/identifiers remain literal argv. This does not authorize any
future general-purpose tool. SAFE-13 now has controlled browser script/text/unsafe-link coverage in
batch sixteen alongside backend formula and original-download checks. SAFE-15
remains partial: adversarial malformed/container/dimension limits are exercised,
Report PDF/DOCX/XLSX parsers now run in a fixed child operation with a
30-second wall/CPU limit, 32 MiB output cap and 768 MiB memory policy. Linux
applies an address-space limit; macOS supervises RSS every 50 ms with a finite
sampling/termination overshoot window. Missing monitoring fails closed. Private
temporary streams do not forward credentials; whole process groups are reaped.
Batch seventeen replaces native MPXJ post-capture checks with bounded pipe
retention and process-group cleanup. Batch eighteen adds native per-process
CPU limits, JVM allocation caps, sampled reader RSS and private environments.
Actual MPXJ fixtures pass on Darwin; aggregate descendant budgets, Linux execution
evidence and every deployment resource boundary are not established; SAFE-15
remains partial. Finite controls/tests do not prove safety against every malicious file.

Regression coverage and remaining acceptance limits are summarized in
[testing and quality](TESTING_AND_QUALITY.md). Raw historical captures stay local.
